## F540 (medium): Guardian article with a lead video gets no Short version, the video and its caption sit above the H1, and a 'Prefer the Guardian on Google' promo is left in

Found by: T2-news. Where: https://www.theguardian.com/world/2026/oct/24/israel-soldiers-raze-west-bank-neighbourhood-hebron-families-from-homes (Sift view, 1280 px)

Evidence: On 3 loads (waits of 8, 15 and 50 s), Sift's shadow root has no <article> element and no 'Show full text' toggle. The full 512-word body is shown as flat paragraphs. The order is: [PORTAL] 'Israeli troops destroy Hebron neighbourhood...' with its controls, the caption paragraph, then H1, byline 'Julian Borger · Oct 24, 2026', standfirst, a second byline 'Julian Borger in Jerusalem', an H2 collapsible 'Sat 24 Oct 2026 14.17 BST', then '[link] Prefer the Guardian on Google' (google.com/preferences/source). In the original the H1 is at y=530 and the video below it at y=708. Other Guardian articles from the same day (Lula, Meghan, France protests, which also has a lead video, Eagle's Nest, Starlink, North Korea) each get an <article class=short>, a toggle, the H1 first, and no Prefer link. Shots: /home/nico/projects/sift-test-2/research/shots/r5t2-guardian-art.png (Sift), /home/nico/projects/sift-test-2/research/shots/r5t2-guardian-art-orig.png (original, behind the consent banner); outline r5t2-guardian-art.txt.

Repro: SIFT_PORT=9462 SIFT_TAB=T2-news bun scripts/visit.ts https://www.theguardian.com/world/2026/oct/24/israel-soldiers-raze-west-bank-neighbourhood-hebron-families-from-homes gu --wait 30000, then eval document.querySelector('sift-root').shadowRoot.querySelectorAll('article').length: it gives 0. Compare with /world/2026/oct/24/lula-brazil-runoff-flavio-bolsonaro: it gives 1, with a Show full text button.

Suspected cause: The article container is not detected on this page, so the walker renders the whole main column, including the meta aside (data-gu-name=meta, which holds the preferred-source button) and the main media before the headline. Something in this page's structure defeats the article picker in generic.ts while the other Guardian articles pass. I did not find which.

Skeptic: Reproduced on 2 loads (20 s and 30 s waits). Sift's shadow root has 0 <article> elements and no Show full text button. The outline order is: PORTAL video and its controls, the caption, then H1, byline, standfirst, a second byline, 'H2 Sat 24 Oct 2026 14.17 BST', then '[link] Prefer the Guardian on Google'. The Lula article has the same data-gu-name structure (media, title, headline, ..., body) and gets 1 article and a toggle. Cause, found with a page-side copy of findArticle: the body's best node climbs to <main>. The prose() climb step counts the 'More on this story' carousel (ul.carousel-small). Its li cards hold only an empty overlay <a> named by aria-label, so their headline text counts as prose and not as link text. For this short story, main prose is 4225 against 3261 for the <article> (ratio 1.30, above the 1.25 limit), so the climb goes on to main. Lula's longer body stays under 1.25. Inference: when articleEl is the root (main), articleScope returns root, and walkPage calls walk(root) on the children only, so article() never runs and no article block is emitted.

Skeptic's fix lead: In src/content/extract/generic.ts findArticle(), in the prose() climb (~2530-2560), count an anchor's accessible name (aria-label) as link text, or skip li cards whose only link is an empty overlay anchor, so onward-story carousels do not tip the climb. Also, in extractGeneric/walkPage, when ctx.articleEl === root, route it through article() (visit the root) instead of walk(root), so a story found at the root still gets its article block and Short version.

## F542 (medium): Infobae sign-in form shows English developer labels instead of the visible Spanish text

Found by: T2-news. Where: https://www.infobae.com/america/ -> INICIAR SESION (Sift dialog)

Evidence: The Sift dialog reads 'keep-me-loggedin' (checkbox), 'login in' (submit button) and 'register button'. The original shows the visible texts 'Recordar', 'Ingresar' and 'REGISTRARME'. These are the site's aria-labels (input aria-label=keep-me-loggedin, button aria-label='login in', 'register button'). The same dialog uses the visible text 'Olvidé mi contraseña' for the button whose aria-label is 'forgot password'. A Spanish-speaking user sees English code-like labels on the main sign-in action. Shot: /home/nico/projects/sift-test-2/research/shots/r5t2-ib-signin.png

Repro: Open https://www.infobae.com/america/ in Sift, click INICIAR SESION, read the checkbox and button labels. Then Escape, Alt+Shift+S, click INICIAR SESION on the original: it shows Recordar / Ingresar / REGISTRARME. Do not submit.

Suspected cause: For these controls the label is taken from aria-label before the visible text, even when the aria-label is a developer string in another language.

Skeptic: Reproduced. The Sift sign-in dialog shows 'keep-me-loggedin' (checkbox), 'login in' (submit) and 'register button'. The original shows Recordar / Ingresar / REGISTRARME (shot research/shots/sk-ib-signin.png). Cause in generic.ts labelOf(): for a button with an aria-label, visible text replaces the aria-label only when it has 3 or more words or 20 or more characters. So 'Olvidé mi contraseña' wins, but 'Ingresar' and 'REGISTRARME' lose to the English aria-labels. For the checkbox, accName() returns aria-label before the wrapping <label> text 'Recordar'. The original's accessible names are the same English strings (a site accessibility bug), but Sift prints them as visible text on a Spanish page, which breaks 'keeps the page's language' on the main sign-in actions.

Skeptic's fix lead: src/content/extract/generic.ts labelOf() (~572): prefer the visible text whenever it is not contained in the aria-label (label-in-name), not only when it is 3 or more words. Do the same for inputs: when an input's aria-label looks like an identifier (hyphenated, or contains 'button'/'input') or does not contain the wrapping label's visible text, use the label text from dom.ts accName().
