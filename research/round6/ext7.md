## F625 (high, regression): NPR home page loses 17 of 38 top stories: a grid member holding several <article>s now drops the whole grid to the walker, which then deletes 'c-promo-card' stories as noise

Found by: R1-extractor. Where: src/content/extract/generic.ts:2165 (nav's rule: members.some(k => k.querySelectorAll('article').length > 1) → return null), together with the NOISE_TOKEN drop in visitEl at generic.ts:3152 ('promo-card' in NOISE_TOKEN, dom.ts:745)

Evidence: Live https://www.npr.org/ with the harness: now 21 items, sift-r5-base 37-38. Each group's bundle gives 37, except sift-r5-nav, which gives 21. A copy of the current tree with only line 2165 removed (scratchpad/r6/mod) gives 38. Missing stories include 'U.S. birth rate drops to record low…', 'Americans can't get enough of mahjong…', 'Ohio could decide control of the Senate…', 'Gunmen open fire at a church…', 'Jet fuel prices hit a record…' and 'Kara Swisher on Elon Musk…'. In the real extension (9468) none of them is in Sift's text, while document.body.textContent has all six. DOM: div (41 kids, 86 <article>s) > div.bucketwrap members. One member holds a nested featured card-wrap with 5 articles, so detectItems returns null. The walker then visits each article.c-promo-card, and the NOISE_TOKEN check drops it ('promo-card'), which toItem never applied. A minimal fixture (scratchpad/r5/fx/promocards.html: 8 promo-card stories plus one member with 3 nested ones) keeps only the 3 nested stories. Pre kept all 11. In the real extension, 'click:plan number 3 for' says 'not found'. Spiegel is the only other of 30 live news fronts where the rule changes output, and it helps there.

Repro: cd scratchpad/rv && python3 -m http.server 8868 in scratchpad/r5/fx; bun batch.ts ../r6/o5 now,pre http://127.0.0.1:8868/promocards.html (now: 3 items, pre: 11). Live: cd scratchpad/r6 && N=1 bun live.ts live4 now,mod,r5-base npr.txt; grep -c '^  \*' live4/www_npr_org_.*.txt

Suspected cause: Returning null for the whole set because one member holds several <article>s hands every card to visitEl. visitEl drops class tokens such as 'c-promo-card' (NOISE_TOKEN 'promo(tion)?-?cards?' and 'promo') before asCard runs. Either exclude only the multi-article members from the set (as ext does for 'boxes'), or skip the NOISE_TOKEN drop for an <article> or card whose heading links a story.

Skeptic: Confirmed, high, regression. I used my own bundles built from sift-test-8 (now), sift-r5-base (pre), and a copy with only generic.ts:2165 removed (mod). On live https://www.npr.org/ the harness gives 21 items for now, 37 for pre and 37 for mod. Stories present in pre and mod but missing from now include 'U.S. birth rate drops to record low…', 'Americans can't get enough of mahjong…', 'Ohio could decide control of the Senate…', 'Gunmen open fire at a church…', 'Jet fuel prices hit a record…', 'Kara Swisher on Elon Musk…' and 'Leon Bridges reinvents his sound…'. On the promocards.html fixture, now keeps only the 3 nested featured stories and pre keeps all 11 headlines. Pre does squeeze 101 and 102 into meta, but story 0 and stories 1-7 survive. The cause is as described: line 2165 returns null for the whole grid, and the walker's NOISE_TOKEN check at generic.ts:3152 ('promo-card'/'promo') then drops each article.c-promo-card.

Skeptic's fix lead: In detectItems (src/content/extract/generic.ts ~2165), do not return null for the whole set when only some members hold several <article>s. Put those members in `boxes`, so they are walked and left out of the set, and return null only when most members hold several articles (the Discourse thread case). As a backstop, skip the NOISE_TOKEN drop in visitEl (~3152) for an <article> or card whose heading holds a story link.

## F626 (medium, regression): pictureTwin makes lists and grids of picture-only links quadratic (~1 s extra per extraction at 3000 entries)

Found by: R1-extractor. Where: src/content/extract/generic.ts:747 (usefulControl calls pictureTwin for every link) and 755-765 (pictureTwin runs box.querySelectorAll('a[href]') up to 4 ancestors deep and only then checks length > 6)

Evidence: Alternating runs in the same page, current tree compared with the same tree minus line 747 (scratchpad/r6/mod2). wallul3000.html (<ul> of 3000 li>a>img alt): now 1265/1132/983/893 ms, without pictureTwin 210/173/201/229 ms. walldiv3000.html (div.cell>a>img): now 2756/1620/1468/1546, without 845/510/578/573. wallul1000: now 187/179/188/153, without 90/59/56/54. sift-r5-base on wallul3000: 275/273/235/185 ms. CPU profile (harness): pictureTwin is the top self-time function. In the real extension's profile, querySelectorAll self time is 6175 ms on wallul3000 vs 133 ms on wall3000 (same links inline in one div). Each li has a single picture link, so the loop climbs to the <ul> and runs querySelectorAll over all 3000 links once per entry. Every re-extraction (mutations, load more) pays it again.

Repro: Serve scratchpad/r5/fx on 8868; cd scratchpad/rv && BASE=./bundle-mod2.js BOTH=1 bun run3.ts http://127.0.0.1:8868/wallul3000.html ../r6/time5.js

Suspected cause: querySelectorAll on a large ancestor per picture link (content group's new helper). Cache the links with words per box per pass (as wordedHrefs does), or count links incrementally and stop at 7.

Skeptic: Confirmed, medium, regression. I built a copy of the current tree with only generic.ts:747 (the pictureTwin call) removed, and ran both bundles on the same page, alternating, 5 runs each. wallul3000: now 1281/1007/1190/1208/1183 ms, without the call 205/239/304/165/155. walldiv3000: now 2023-3748 ms, without 857-1284. wallul1000: now 207-387 ms, without 74-160. wall3000 (links inline in one div, no climb): now 255-743 ms, without 227-511, so roughly the same. Real extension profile.ts on wallul3000: querySelectorAll self time 6840 ms, with pictureTwin in the hot list. On wall3000 it was 92 ms. The code matches the claim: for each picture-only link, the loop climbs to the big list and runs box.querySelectorAll('a[href]') over every link before the length > 6 break. That is quadratic. It only shows at roughly 1000+ untwinned picture links (galleries, avatar walls), and it repeats on every re-extraction.

Skeptic's fix lead: In pictureTwin (src/content/extract/generic.ts ~755-765), stop before the full query on a big box. Either count the box's links with an early exit at 7, or cache per extraction pass a map of box to (link count, hrefs that have words), as wordedHrefs does, so each ancestor is scanned once.

## F627 (medium, regression): ctaStrip deletes 'Already have an account? [Log in]' and 'Need help? [Visit the help centre]' when the link is button-styled and goes to a subdomain

Found by: R1-extractor. Where: src/content/extract/generic.ts:3168 (if (tlen(el) < 120 && ctaStrip(el)) return;) and 774-788 (ctaStrip: one link with a btn/button/cta class to another host of the same site, plus 8-60 characters of other text)

Evidence: Fixture scratchpad/r6/fxl/ctalogin.html, served as http://fixture.test/page: a sign-up form, then <div>Already have an account? <a class="btn btn-secondary" href="https://account.fixture.test/login">Log in</a></div> and <div>Need help? <a class="btn" href="https://help.fixture.test/">Visit the help centre</a></div>. Now: only h1, intro and the form; both lines and their links are gone. Pre: 'p(small): Already have an account? [Log in ->/login]' and 'p(small): Need help? [Visit the help centre ->/]'. The rule targets La Nación's radio cross-promo. It also matches any short strip whose one button-styled link goes to the site's own account., help., app. or my. subdomain, which is common for sign-in and help.

Repro: cd scratchpad/rv && bun run3.ts ../r6/fxl/ctalogin.html ol.js; BUNDLE=./bundle-pre.js bun run3.ts ../r6/fxl/ctalogin.html ol.js

Suspected cause: ctaStrip has no test that the target is another product (a promo) rather than the user's account, sign-in or help. Restrict it to links whose text or slogan sells (PROMO_LABEL-like words, 'Escuchá', 'Listen', 'Play'), or exclude sign-in, account and help links and pages that hold a form.

Skeptic: Confirmed, medium, regression. Harness on ctalogin.html served as http://fixture.test/page: now gives h1, intro and the form only, and both lines are gone. Pre gives 'p(small): Already have an account? [Log in ->/login]' and 'p(small): Need help? [Visit the help centre ->/]'. Real extension (9468, same URL via request interception): Sift shows the heading, the intro, the email field and 'Create account', and nothing else, while the original page text has 'Already have an account? Log in' and 'Need help? Visit the help centre'. ctaStrip (generic.ts:774-788) matches: a single link with a btn class, a different host on the same site, 8-60 characters of other text, and no heading, p or form inside the strip. A sign-up page linking to its accounts. or help. subdomain with a Bootstrap-style button link is common, and losing 'Log in' there removes a control the user needs.

Skeptic's fix lead: In ctaStrip (src/content/extract/generic.ts ~774), exclude account, sign-in and help targets: drop the match when the link text or path matches sign in, log in, account, help or support, or when the page holds a form. Better still, require selling words like La Nación's ('Escuchá', 'Listen', 'Play', 'Descargá', 'Download the app') before treating the strip as a cross-promo.

## F566 (still open, partly; original repro in /home/nico/projects/sift/research/round5/*.md)

Recheck by R1-extractor: The fixture with onclick works. hashlink.html gives '[How do I change the delivery address…? ->…#]'. In the real extension, act 'click:How do I change' opens the answer: 'Open Your orders…' appears and #a1.hidden is false. Skeptic: Confirmed as partly fixed. Real extension: on hashlink.html (onclick), both questions are links. 'click:How do I change' opens the answer: 'Open Your orders…' appears and the answer's hidden is false. On hashlink2.html (same FAQ, wired with addEventListener only), both questions are plain 'p:' text. 'click:How do I change' says 'not found', and the answer stays hidden (hidden is true). scriptLink (generic.ts:831) only checks onclick, data-action, aria-* and role, and the isolated world cannot see listeners added by page scripts. So the guards at generic.ts:1017 and 3458 still turn listener-only long '#' links into text.

Skeptic's fix lead: In src/content/extract/generic.ts (~1017 and ~3458), stop turning a bare href='#' link into text: keep it as a link or action, since proxy.ts replays the click on the original. Or have src/main/index.ts hook EventTarget.prototype.addEventListener for click on anchors and mark them (a data attribute), so scriptLink can see them. Delegated listeners would still be missed by the hook, so keeping bare '#' links clickable is the more robust fix.
