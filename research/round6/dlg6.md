## F600 (high): Gmail-style toast: the Undo link (span role=link) is shown as plain text, so Undo cannot be used from Sift

Found by: T5-amazon-gmail-a11y. Where: src/content/extract/generic.ts toastButtons() (about line 5563): it collects only 'button, [role=button], a[href]', so [role=link] is left out. findToast() then turns the rest into notice text. Seen on the new fixture http://127.0.0.1:8799/fx/r6t5-gmailtoast.html (/home/nico/projects/sift/research/fixtures/r6t5-gmailtoast.html). That fixture is gmail.html plus Gmail's archive toast: a role=alert box, 'Conversation archived.', Undo as <span id=link_undo role=link tabindex=0>, and a Dismiss icon with role=button.

Evidence: After Sift's Archive on the first email, the original shows 'Conversation archived.  Undo'. Sift's notice is <p class="notice warn">Conversation archived. Undo<button>Dismiss</button></p>. 'Undo' is plain text, and no Sift control has the text Undo (count 0). The variant without Dismiss (?nodismiss=1) gives a notice with text only and no buttons. Control variant ?btn=1, where Undo is a <button>: Sift shows Undo and Dismiss as buttons, and clicking Undo restores the email (mails [1,2,3], __undone=1, the page says 'Action undone.'). So the round-5 toast-buttons path works, but not for Gmail's markup. In both variants, the live region also said only 'Removed: Your class schedule for next week.' The toast's text, and the fact that Undo exists, were never announced, because paint()'s say('removed') replaces notify()'s say. Shots: /home/nico/projects/sift-test-5/research/shots/r6t5-gmailtoast-sift.png, /home/nico/projects/sift-test-5/research/shots/r6t5-gmailtoast-nodismiss.png, /home/nico/projects/sift-test-5/research/shots/r6t5-z200-gmailtoast.png. Caveat: the fixture is synthetic. It is modeled on Gmail's known toast markup, where 'Undo' is #link_undo and 'View message' after Send is #link_vsm, both span role=link. That markup comes from my knowledge of Gmail, and I did not check it on live Gmail (sign-in is not allowed).

Repro: cd /home/nico/projects/sift-test-5; SIFT_PORT=9465 SIFT_TAB=x bun scripts/act.ts goto:http://127.0.0.1:8799/fx/r6t5-gmailtoast.html wait:4000 click:Archive wait:2000 "eval:document.querySelector('.b8').innerText" "eval:document.querySelector('sift-root').shadowRoot.querySelector('.bar-notice')?.outerHTML" "eval:[...document.querySelector('sift-root').shadowRoot.querySelectorAll('button,a')].filter(b=>/undo/i.test(b.innerText)).length". This prints the original toast with Undo, a Sift notice with only a Dismiss button, and 0. Control: goto:http://127.0.0.1:8799/fx/r6t5-gmailtoast.html?btn=1, then click:Archive, click:Undo, and "eval:mails.map(m=>m.id)" prints [1,2,3].

Suspected cause: toastButtons() does not treat [role=link] (or a focusable [tabindex] element with a click role) as a toast action. Gmail's toast actions are spans with role=link. Separately, when a list action removes the focused item, paint()'s say(t('removed')) runs after notify(toast.text, 0, toast.said), and say() keeps only the last text, so the toast is never read out.

Skeptic: Confirmed. I reproduced it twice on http://127.0.0.1:8799/fx/r6t5-gmailtoast.html in the 9465 test Chrome, with trusted clicks. After Sift's Archive on the first email, the page's toast reads 'Conversation archived.  Undo'. Sift's notice is <p class="notice warn">Conversation archived. Undo<button ... data-ref="r11">Dismiss</button></p>. In Sift's shadow root, no button, link, [role=link] or [tabindex] element has the text Undo (count 0). The archived email stays gone (mails [2,3]). With ?nodismiss=1 the notice is text only ('Conversation archived. Undo') with no buttons. That matches the code: findPopup's actionable check at generic.ts:5212 also leaves out [role=link], so the toast falls to the 5-second text path. In the control ?btn=1, Sift shows Undo and Dismiss as buttons, and clicking Undo restores the email (mails [1,2,3], __undone=1, the page says 'Action undone.'). With Sift off (Alt+Shift+S), clicking the span#link_undo on the original also restores [1,2,3] with 'Action undone.', so Sift loses an action the original has. The announcement part also holds. A MutationObserver on Sift's only live region (div.sr role=status) recorded only 'Removed: Your class schedule for next week.'. The toast text was never placed there, because the say() in paint() for the removed item cancels the earlier say() from notify() inside its 100 ms timer. The original's own role=alert sits under the inert page, so nothing else announces it. Code check: toastButtons() at generic.ts:5564 queries only 'button, [role=button], a[href]'. Caveat: the fixture is synthetic. Its markup (span#link_undo role=link tabindex=0) matches Gmail's widely known toast markup, and the Gmail adapter already handles Reply and Forward as [role=link] spans (gmail.ts:226-228). I did not check live Gmail. The bug is in Sift's selector either way, because role=link is valid ARIA for a toast action.

Skeptic's fix lead: In src/content/extract/generic.ts, add focusable [role=link] elements (for example '[role=link]:not([tabindex="-1"])') to two places, and keep them in step. One is toastButtons() (line ~5571, 'button, [role=button], a[href]'). The other is findPopup's actionable test (line 5212). If only one changes, line 5416 (pop.actionable && !actionToast) may turn the toast into a dialog. Also check that toAction() and the proxy replay a click on a span with role=link. In src/content/index.ts paint() (line ~415), when a notice was set during the same action, do not let say(t('removed', …)) replace notify()'s say(said). Either combine the two strings ('Removed: X. Conversation archived. Undo'), or make say() append text that arrives within its 100 ms window instead of replacing it.

## F601 (high, regression): A page modal with no close button of its own (sign-up nag that does not block the page) can no longer be dismissed in Sift; the whole page is locked, and a backdrop click strands keyboard focus on the original's body

Found by: T6-fixtures. Where: http://127.0.0.1:8799/fx/int-nag.html (role=dialog aria-modal=true box, no overlay, holding 'Sign up' and a 'Maybe later' link that only logs)

Evidence: Sift shows a modal sheet 'Join the forum' (Sign up | Maybe later) with no Close, and main.inert=true. Escape keeps it (2 of 2 fresh loads). 'Maybe later' logs 'later', and the sheet stays. Tab cycles only Sign up and Maybe later. After a click on the backdrop at (5,500), the sheet stays and focus goes to the original's <body>. Four Tabs then all stay on body: keyboard focus never comes back into Sift. On the original, the page text and the 'Gardening threads' link stay visible and clickable (elementFromPoint at the link returns #go). The round 3/5 works line 't_nag (a dismissed nag stays dismissed after SPA nav)' no longer holds: the old t_nag.ts fails with 'no .layer button Close'. Shots /home/nico/projects/sift-test-6/research/shots/r6t6-nag-open.png and r6t6-nag-original.png.

Repro: cd /home/nico/projects/sift-test-6 && SIFT_PORT=9466 SIFT_TAB=T6-fixtures bun scripts/act.ts goto:http://127.0.0.1:8799/fx/int-nag.html wait:3000 press:Escape wait:1000 "eval:(()=>{const R=document.querySelector('sift-root').shadowRoot;const s=R.querySelector('.layer .sheet');return (s?'SHEET '+s.innerText:'nosheet')+' main.inert='+R.querySelector('main').inert})()" (sheet still there, main.inert=true). Focus trap: cd /tmp/claude-1001/-home-nico/aac11194-acaf-4dad-a334-0620115b1898/scratchpad/r6 && SIFT_PORT=9466 SIFT_TAB=T6-fixtures bun nagkb.ts (after the backdrop click, every Tab stays on 'body').

Suspected cause: The F522 fix in the dialog code (H.closeDialog / sheet rendering in index.ts and app.tsx) drops Sift's Close for any modal without its own close control. It does not check whether the page modal actually blocks the content (a full-screen overlay or backdrop, as on consent walls and age gates). Also, a backdrop click on a sheet with no close moves focus to the original page.

Skeptic: Reproduced on 2 fresh loads of int-nag.html. Sift shows the sheet 'Join the forum' with only Sign up and Maybe later. There is no Close, and main.inert=true. Escape keeps the sheet (log []). 'Maybe later' logs 'later' and the sheet stays. Tab cycles only Maybe later and Sign up. After a click on the backdrop at (5,500), focus goes to the original's body, and 4 Tabs all stay on body. With Sift off, the page is usable: elementFromPoint at the link returns #go, and body.inert=false. The old round 4 t_nag.ts fails with 'no .layer button Close'. Cause in code: blocksPage() in generic.ts returns true for aria-modal=true alone, so blocking=true and app.tsx drops Close. Scope: if 'Maybe later' really removes the dialog (I patched its handler on the page), the sheet closes correctly. So the full lockout needs a nag whose own dismiss does nothing. The backdrop focus loss is broader. It happens on every blocking sheet: on r4-cookiewall.html?gate=1, a backdrop click also left focus on body, and Tab never came back into the sheet. Only Alt+Shift+S gets out.

Skeptic's fix lead: In extract/generic.ts blocksPage(), do not count aria-modal=true as blocking unless a full-window fixed overlay covers the page, it is a :modal <dialog>, or it is a consent wall (wall). A non-blocking modal then gets Sift's Close again. In app.tsx Dialog, the .layer handler for a blocking sheet should keep focus in the sheet (onMouseDown preventDefault plus box.current.focus()) and not let it fall to body.

## F603 (high): A bulk-action bar that appears after selecting a row becomes a modal sheet that blocks further selection; once closed, 'Mark as shipped' and 'Print labels' never come back

Found by: T6-fixtures. Where: New fixture http://127.0.0.1:8799/fx/r6-bulktable.html (a position:fixed bottom bar, hidden until a row checkbox is ticked: 'N selected | Mark as shipped | Print labels | Clear selection')

Evidence: Ticking 'Select order 2002' (by mouse, or Space by keyboard) logs 'pick 2002'. Sift then opens a modal sheet '1 selected' (Close, Mark as shipped, Print labels, Clear selection), with main.inert=true and focus on Close. The user cannot tick a second row: a click on 'Select order 2004' only closes the sheet (no 'pick 2004'), and focus lands on the original's body. From then on the page bar stays visible (#bulk hidden=false, after 'pick 2004' and 'all true'), but Sift shows no 'Mark as shipped' anywhere, even after switching Sift off and on. Escape on the sheet gives the same dead end. On the original, the bar stays at the bottom while more rows are ticked. Shot /home/nico/projects/sift-test-6/research/shots/r6t6-bulk-sheet.png.

Repro: cd /tmp/claude-1001/-home-nico/aac11194-acaf-4dad-a334-0620115b1898/scratchpad/r6 && SIFT_PORT=9466 SIFT_TAB=T6-fixtures bun bulk2.ts (line 1: modal SHEET with focus on Close; line 3: no 'pick 2004', 'nosheet', inMain=0, page bulk hidden false), then bun bulk3.ts (shipBtns=0 after another pick and after Sift off/on). Keyboard: bun bulkkb2.ts.

Suspected cause: The F518 fix keeps fixed bars only when they are present at extraction. A bar that appears after a checkbox change goes down the recent-popup path and is shown as a modal dialog. Closing it marks it dismissed, so it is filtered out for good. A fixed, non-modal bar of buttons that is outside nav/header, and not role=dialog, should render in place like the sticky checkout bar.

Skeptic: Reproduced by mouse and by keyboard. Ticking 'Select order 2002' logs 'pick 2002'. Sift then opens a modal sheet (role=dialog, aria-modal=true) holding 'Close | 1 selected | Mark as shipped | Print labels | Clear selection', with main.inert=true and focus on Close. A click on 'Select order 2004' only closes the sheet: no 'pick 2004', and focus goes to the original's body. The page bar stays shown (#bulk hidden=false), but Sift has 0 ship or print buttons. That stays true after another pick ('pick 2005' logged) and after switching Sift off and on. Space then Escape gives the same result: the sheet is gone for good, and focus returns to the checkbox. Bulk actions on more than one row cannot be done in Sift.

Skeptic's fix lead: In extract/generic.ts findPopup() and the popup branch of the dialog extraction, do not treat as a popup a fixed bar that spans the window width at the top or bottom, is not role=dialog or aria-modal, and holds only buttons and short text. Render it in place through the F518 fixed-bar path. Also, a bar dismissed this way should not stay in store.dismissed while it is still shown.
