## F900 (medium, regression): YouTube watch: text typed into Sift's search box during page load often never reaches YouTube's field; Enter and Search then do nothing

Found by: T5-amazon-gmail-a11y. Where: https://www.youtube.com/watch?v=dQw4w9WgXcQ, Sift's header search box, while the page loads (Sift's field shows at 1.5-3.5 s)

Evidence: works.md round 8 line 96 says typing 'abc' during the load reached both fields. I ran research/r9t5/earlytype.ts 8 times. It clicks Sift's search box as soon as it shows and types 'abc', then waits 8 s. Sift kept focus in its field and showed 'abc' every time. YouTube's input[name=search_query] stayed '' in 6 of 8 runs (field shown at 1890, 1613, 3014, 1551, 2575 and 2341 ms). It got 'abc' in 2 runs (3547 and 1796 ms). In the failing runs, Enter left the URL at watch?v=dQw4w9WgXcQ. Clicking Sift's Search button also did nothing, and the page value stayed ''. Control: typing after load syncs at once (['xyz','xyz']), and 'abc' plus Enter gives /results?search_query=abc. On the original with Sift off, typing as soon as YouTube's own box showed (1.9-4.1 s, 5 runs) kept 'abc' in the box every time. YouTube then moved focus to the video player (div.html5-video-player), so Enter did not search there either, but the typed text stays in the page's box. In Sift, the text the reader sees in the focused field is not what the page has, and both ways to submit fail silently. Shots: /home/nico/projects/sift-test-5/research/shots/t5r9-yt-earlytype-1.png, /home/nico/projects/sift-test-5/research/shots/t5r9-yt-earlytype-3.png

Repro: cd /home/nico/projects/sift-test-5 && SIFT_PORT=9465 ./scripts/chrome.sh start && for i in 1 2 3; do SIFT_PORT=9465 SIFT_TAB=x bun research/r9t5/earlytype.ts "https://www.youtube.com/watch?v=dQw4w9WgXcQ" "input[name=search_query]"; SIFT_PORT=9465 SIFT_TAB=x bun scripts/act.ts press:Enter wait:3000 url; done  (a failing run prints siftValue:'abc', pageValue:'' and then the unchanged watch URL; a passing run ends at /results?search_query=abc. Expect at least one failure in 3 runs.)

Suspected cause: Sift shows its search field before YouTube's yt-searchbox input exists or has hydrated. The keys Sift replays go to no field, or to one YouTube replaces. Nothing re-applies Sift's value when the page's input appears, and the submit then replays on the empty page input. A lead: when a proxied text field's original element appears or changes and its value differs from Sift's, write Sift's value into it. At the latest, set it just before replaying Enter or the submit.

Skeptic: Reproduced on live YouTube watch (dQw4w9WgXcQ). I ran the tester's earlytype.ts 4 times: 1 failed. My own script (/tmp/claude-1001/-home-nico/aac11194-acaf-4dad-a334-0620115b1898/scratchpad/early-diag.ts) clicks Sift's field as soon as it shows (1.5-3.5 s), types 'abc', waits 8 s, then submits. Over 10 runs, 4 failed (2 with Enter, 2 with Sift's Search button). In every failing run Sift's focused field showed 'abc', the only input[name=search_query] had '', and the URL stayed on watch?v=dQw4w9WgXcQ after the submit. Passing runs went to /results?search_query=abc. Total: 5 failures in 14 runs. An input-event log in the page shows the cause. The keys reach a first yt-searchbox input ('a', 'ab', 'abc'). Then YouTube puts in a new input with value '' (for example 'appear' at 2401 ms after 'abc' at 1993 ms), and Sift never writes its value into it. Original with Sift off, 3 valid runs: YouTube's own box showed later (2.6-3.9 s) and kept 'abc' 3 of 3 times. YouTube then moved focus to the video player, so Enter did not search on the original either. But the page's text stayed, and its own search button would still work. In Sift the field shows text the page does not have, and both Enter and the Search button fail silently. That is a Sift bug. Medium fits: search is a core action, and the failure is silent but only in the load window. Typing one more character heals it, because setValue writes the whole value. I could not check the 'regression' part: round 8 may simply not have hit this race.

Skeptic's fix lead: src/content/index.ts. liveField() writes Sift's value into a swapped field only when elOf(ref) is null (the F850 path). Here the ref already points at YouTube's new, empty input, so that path never runs. Fix in the submit handler (index.ts around line 3283): after liveField(field.ref), if fieldEl is a plainField and Sift's input[data-ref=field.ref] has a different value, call proxy.setValue(fieldEl, mine.value) before proxy.submit. Better also: when a re-extraction maps a ref Sift's user is typing in to a new element, do the same sync there (the existing 'sync && mine && mine.value !== now.value' line).

## F905 (high): Nested replies in a comment thread lose their text: only the replier's name and time stay, merged into the parent's meta line

Found by: T6-fixtures. Where: http://127.0.0.1:8799/fx/r8ext11-thread.html and r8ext11-nested-comments.html (seen while rechecking F836)

Evidence: In r8ext11-thread, dana's comment has 2 replies by ed: 'Agreed, and the crossing by the library needs a light too.' and 'The council meets on Tuesday about that light, if you want to speak.' Sift's text has neither. Sift innerText.includes('Agreed') is false, and the page's is true. dana's item becomes 'dana | 2 hours ago · ed · 1 hour ago', with the two replies collapsed into one meta. Harness outline: no replies under the item, in both the merged and the sift-r8-base bundles. F836's report had already noted 'The replies' own text is missing in both builds', but no finding id tracks it. Shot: /home/nico/projects/sift-test-6/research/shots/r9t6-thread-replies.png

Repro: SIFT_PORT=9466 SIFT_TAB=T6-fixtures bun /tmp/claude-1001/-home-nico/aac11194-acaf-4dad-a334-0620115b1898/scratchpad/r9t6/go.ts goto:http://127.0.0.1:8799/fx/r8ext11-thread.html wait:3000 "sx:R.querySelector('.sift').innerText.includes('Agreed')" "eval:document.body.innerText.includes('Agreed')" prints false then true.

Suspected cause: toItem (generic.ts) reads a card's own text and meta and skips nested li entries. Their author and time links leak into the parent's meta, and their paragraphs are never kept as Item.replies.

Skeptic: Reproduced on both fixtures and on a real site. In r8ext11-thread, Sift has no 'Agreed' and no 'council meets' (both false), while the page has them (true). dana's item reads '2 hours ago · ed · 1 hour ago', with the reply author merged into the parent's meta. In r8ext11-nested-comments, the page has 10 'Reply N to comment' texts and Sift has 0. Each parent's meta ends with '· maria_lopez'. Live lobste.rs (/s/olnqh2/websites_should_be_printable) shows the same. Each top-level comment becomes a one-line summary item, and its replies show only author and time links in the meta (e.g. 'chrismorgan 11 hours ago · bputh 6 hours ago'). Reply texts such as 'My bad on your first point,' and 'This is a great trick, thanks!' are nowhere in Sift. Side note: that item's title links to the w3.org URL inside the comment rather than to the comment. The WordPress-style case (comments under an article, behind the 'Comments' section) does keep replies, so the bug is specific to the item/list path. Code: model.ts has Item.replies and app.tsx renders it, but only the YouTube adapter fills it, and generic.ts never does. High: whole conversations are lost on forum and thread pages.

Skeptic's fix lead: In generic.ts toItem (the card/list-entry builder), detect a nested list of entries inside the card (ul/ol of li with the same shape, or class replies/children/comments). Build those li entries recursively as Items into it.replies, as youtube.ts does at ~line 836. Exclude them from the parent's own text and meta collection, so their author and time links stop leaking into the parent's meta line.
