## F800 (medium): Gmail compose at 200% zoom or 400 px: Escape or Sift's Close hides the draft only in Sift, and there is then no way back to it (F700 leftover)

Found by: T5-amazon-gmail-a11y. Where: http://127.0.0.1:8799/fx/gmail.html at a 640x450 CSS px viewport (1280x900 at 200%) or 400x800

Evidence: Tested at 640x450, scale 2. Compose opens as a modal sheet 'New Message' (aria-modal=true, main.inert=true). After typing 'a@b' and pressing Escape: Sift has no dialog and no draft, while the page's compose is still open with To 'a@b'. Opening 'Your package was delivered' and then Back to Inbox: Sift's text still has no 'a@b' and shows no draft. Clicking Compose again gives an empty sheet, and the page's To becomes '' (the draft is lost on this fixture). At 400x800 the first three steps give the same result. On the original page at the same size, Escape and clicks elsewhere leave the draft open and visible. At 1280x900 the draft is an inline form and all of this works (see F700 recheck). With a page close control (r7dlg8-gmail-saveclose.html?es=1), Escape runs 'Guardar y cerrar' and the page saves the draft, so the problem needs a compose box with no close control. Shots: /home/nico/projects/sift-test-5/research/shots/t5r8-f700-z200-open.png, /home/nico/projects/sift-test-5/research/shots/t5r8-f700-z200-after.png, /home/nico/projects/sift-test-5/research/shots/t5r8-f700-z200-compose-again.png

Repro: cd /home/nico/projects/sift-test-5 && SIFT_PORT=9465 ./scripts/chrome.sh start && SIFT_PORT=9465 SIFT_TAB=x bun research/r8t5/f700-zoom.ts 640 450 2   (prints 'Escape: siftDialog:null, siftTo:null, pageTo:a@b', then 'back: ... Sift text has a@b: false', then 'Compose: siftTo:"", pageTo:""'). Same with arguments 400 800 1. Control: 1280 900 1 gives an inline form (siftDialog:null, inert false).

Suspected cause: floatingCompose() in src/content/adapters/gmail.ts treats a compose box as floating only when its area is under 50% of the viewport. At 640x450 the 500x400 box is 69%, so composeDialog() makes it page.dialog. Its dismissal now persists, because the ref was added. The box has no close control to replay, so Sift hides it and keeps it hidden while the page still shows it. A lead: never let Escape or Close dismiss a compose dialog that has no close of its own (render it as the inline form instead), or base 'floating' on the absence of a backdrop rather than on area.

Skeptic: Reproduced, but this is the same defect as the F700 recheck (the reporter calls it the F700 leftover). Merge it into F700 rather than giving it a new id. At 640x450 scale 2 (twice) and 400x800, Escape and Sift's Close both remove the 'New Message' sheet. Sift then has no To field, no input values and no 'New Message' heading anywhere. The page's compose stays visible with To 'a@b'. Opening an email and going Back to Inbox does not bring it back. Switching Sift off and on does not bring it back either; only the original view shows it. Pressing Compose again empties the page's draft, which is the fixture's own behavior. At 1280x900 the inline form works. It needs a compose box with no close control that COMPOSE_CLOSE matches. Real Gmail in English or Spanish has 'Save & close', so real-world reach is limited, but it matches the standard used to accept F700. Medium on the fixture. Not a regression in the strict sense: it is the outcome the F700 skeptic predicted if only the ref were added.

Skeptic's fix lead: Same as F700: in src/content/adapters/gmail.ts, make floatingCompose() true for a compose box with no COMPOSE_CLOSE control, or decide on backdrop or maximized state instead of the 50% area rule. Composeform() then renders it inline and it is never a dismissable page.dialog. Or have closeDialog() in src/content/index.ts undo the dismissal when there is no closeRef and the page still shows the box after Escape.

## F803 (medium): Sift's relay of the page's live region glues control names together ('9:009:3010:3014:0016:30')

Found by: T6-fixtures. Where: http://127.0.0.1:8799/fx/r8-slots.html, the time list after a day is picked. src/content/index.ts newAlert(): text = el.innerText.replace(/\s+/g,' ')

Evidence: After a click on 'Tue Nov 3', Sift's only status region (div role=status aria-live=polite) holds '5 free times on Tuesday, November 3 9:009:3010:3014:0016:30'. Thu Nov 5 gives '4 free times on Thursday, November 5 9:0010:3011:0014:00'. The page's aria-live region holds separate buttons (9:00, 9:30, …) with no whitespace between them, as React-built lists usually do. A screen reader reading the page's own region names each button. Sift's text reads as one run-on number.

Repro: cd /home/nico/projects/sift-test-6 && SIFT_PORT=9466 SIFT_TAB=T6-fixtures bun research/r8t6/go.ts goto:http://127.0.0.1:8799/fx/r8-slots.html wait:2500 "click:Tue Nov 3" wait:1800 "eval:[...document.querySelector('sift-root').shadowRoot.querySelectorAll('[role=status]')].map(e=>e.textContent).join('|')"

Suspected cause: innerText puts no separator between adjacent inline-block controls. The relay should join the accessible names of the region's child elements (or insert a space between element boundaries) instead.

Skeptic: Reproduced twice. After 'Tue Nov 3' was clicked, Sift's only polite status region held '5 free times on Tuesday, November 3 9:009:3010:3014:0016:30', and the listener recorded the same string as said. The page's own #slots innerText is '...November 3\n\n9:009:3010:3014:0016:30'. newAlert() uses el.innerText.replace(/\s+/g,' '), and innerText puts no separator between adjacent inline-block buttons that have no whitespace between them. While Sift is shown the page is inert, so this relay is all a screen reader hears. The original's region exposes each time as its own button. The run-on string is not a usable list of times. It is at the low end of medium: the first clause ('5 free times...') reads correctly, and the buttons can still be found in Sift's view.

Skeptic's fix lead: In newAlert() in src/content/index.ts, build the text from the region's nodes, not raw innerText. Walk the subtree and join text nodes, adding a separator (', ' or a space) at each element boundary for buttons, links, inline-block elements and elements with roles. Or join the accessible names of interactive descendants. Then collapse whitespace.
