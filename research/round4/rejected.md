## rejected [medium] Short version of a 167-word video description is 162 words and repeats a sentence
- **where**: YouTube watch https://www.youtube.com/watch?v=nM29yj_D8NE, Description (Short version)
- **evidence**: The original description (Google TechTalk abstract) is 167 words and 1197 characters. Sift's SHORT VERSION is 162 words and 1118 characters, about 3% shorter. It also says the same thing twice: 'This 2025 Google TechTalk presents a per-instance method for measuring how hard it is to unlearn data through fine-tuning.' and two sentences later 'The talk presents a per-instance method for measuring how hard it is to unlearn data through fine-tuning.' Screenshot: /home/nico/projects/sift-test-1/research/shots/R4T1-F14-A-short.png. This goes beyond F72 (25-30% shorter): here the text is not shortened at all and gets padding.
- **repro**: SIFT_PORT=9461 SIFT_TAB=T1-youtube bun scripts/act.ts goto:https://www.youtube.com/watch?v=nM29yj_D8NE wait:9000 click:Description wait:30000 "eval:[...document.querySelector('sift-root').shadowRoot.querySelectorAll('details')].find(d=>/Descri/.test(d.querySelector('summary').innerText)).innerText". It is cached now, so the result is immediate. Count the words against the original description.
- **suspectedCause**: For short sources (150-200 words) the condense prompt's 'at most 50% words' cap is not enforced on the output. A result that is not meaningfully shorter (for example over 80% of the source) should be dropped so the full text shows.
- **verdict**: Not a bug in the current build: a harness artifact. I saw the 162-word Short version with the repeated sentence, served from cache. Hooking crypto.subtle.digest in the worker showed it hashing 'condense|6|...'. Debugger.getScriptSource showed the running background.js was 32,939 chars with PROMPT_VERSION = 6 and no MAX_RATIO, while dist/background.js has PROMPT_VERSION = 7 and the MAX_RATIO 0.7 'not much shorter' check. So the test Chrome on 9461 was running a stale, pre-round-3 service worker. After `SIFT_PORT=9461 ./scripts/chrome.sh reload` the worker ran the current build (v7, MAX_RATIO). A fresh condense of the same description gave a Short version of about 102 words (about 61% of 167) with no repeated sentence. The cached 162-word text, run through the current check, gives a token ratio of 0.94, which the current code rejects. AI-based observations made in this Chrome before a reload (N7, N9 and N12 at least) came from the old background code.

- **where**: Gmail fixture compose dialog; H.closeDialog in src/content/index.ts:1763-1779
- **evidence**: Sift renders the compose as aria-modal=true with focus trapped (Tab cycles Close > To > Subject > Body > Send > Discard draft). So the inbox and thread cannot be read while composing; Gmail's compose window is non-modal. Close sends Escape to the page. The fixture ignores it, so the original compose stays open (Subject 'Draft kept?', display block). Sift marks the dialog dismissed and shows no compose and no control to return to it. Clicking Compose again in this fixture replaces the draft with empty fields. Real Gmail closes compose on Escape and saves the draft (not verified here).

After Sift's Close, the original compose stays open with display block and Subject 'Draft kept?'. Sift then shows no dialog and no way back. The cause is the fixture.
