The same happens on playlist 'Hip 70's' (Fred Shlesinger, 1 / 25, 25 items) opened from Up next. It also happens on 'Gluten-Free Bread' (Ela Vegan, 1 / 28) opened from search results: under the bot check the original still shows the panel with all items, loop and shuffle, but Sift shows only the notice and Comments. A user who opens a playlist from Sift's own results cannot see it or pick another video in it. Screenshots: /home/nico/projects/sift-test-1/research/shots/R4T1-mix-watch.png, R4T1-playlist-watch.png, R4T1-playlist-page.png (Sift) vs R4T1-playlist-page-orig.png (original)
- **repro**: SIFT_PORT=9461 SIFT_TAB=T1-youtube bun scripts/act.ts "goto:https://www.youtube.com/watch?v=dQw4w9WgXcQ&list=RDdQw4w9WgXcQ&start_radio=1" wait:10000 "eval:[...document.querySelectorAll('ytd-playlist-panel-renderer')].filter(p=>p.checkVisibility()).map(p=>p.querySelectorAll('ytd-playlist-panel-video-renderer').length)" "eval:[...document.querySelector('sift-root').shadowRoot.querySelectorAll('summary')].map(s=>s.innerText)". The first gives [25], and the second has no playlist section.

- **verdict**: Reproduced twice. On the Mix watch page (watch?v=dQw4w9WgXcQ&list=RD...) the original has a visible ytd-playlist-panel-renderer with 25 items titled 'Mix - Rick Astley - ...'. On watch?v=L4OakSMck5Y&list=PLhFMhOtiR0RMa55RWT_gKapWYrhCZyZOH (under the bot check), the original panel reads 'Gluten-Free Bread / Ela Vegan / 1 / 28' with 26 rows. Sift shows the notice, the title, Description, Up next and Comments, with no playlist. In the code, watch() in youtube.ts never reads ytd-playlist-panel-renderer.

## F301 [high] Settings menu: 'Display language' and 'Restricted Mode' close the menu instead of opening their page; the dialog is named 'Appearance: Light'
- **where**: YouTube any page, Sift header 'Settings' (top-bar menu added in round 4)
- **evidence**: In Sift, Settings opens a sheet: 'Your data in YouTube | Appearance: Light | Display language: English | Restricted Mode: Off | Location: United States | Keyboard shortcuts | Settings | Help | Send feedback'. Clicking 'Display language: English' gives no dialog in Sift, and the original's ytd-multi-page-menu-renderer is no longer visible: the menu closed. 'Restricted Mode: Off' does the same. In original mode the same click on Display language opens the language list ('Display language | Buttons and display text on this browser | Afrikaans | Azərbaycan | ...'). 'Keyboard shortcuts' does open its sheet. 'Appearance: Light' is plain text, not a button. The sheet's accessible name is 'Appearance: Light' (aria-label taken from the first item); it has no heading. Screenshots: /home/nico/projects/sift-test-1/research/shots/R4T1-settings2.png, R4T1-settings-lang-sift.png, R4T1-settings-lang-orig.png
- **repro**: SIFT_PORT=9461 SIFT_TAB=T1-youtube bun scripts/act.ts "goto:https://www.youtube.com/results?search_query=bread" wait:9000 click:Settings wait:2500 "click:Display language" wait:2500 "eval:[!!document.querySelector('sift-root').shadowRoot.querySelector('[role=dialog]'), [...document.querySelectorAll('ytd-multi-page-menu-renderer')].filter(e=>e.checkVisibility()).length]" gives [false,0]. Compare in original mode (press:Alt+Shift+S): click the ⋮ button, then Display language, and the list opens.
- **suspectedCause**: The click replay on a multi-page menu item does not keep YouTube's iron-dropdown open (the dropdown probably closes on the replayed pointer sequence or a focus change), so the sub-page never renders. Separately, the dialog name falls back to the first item's text.
- **verdict**: Reproduced twice for Display language and once for Restricted Mode. After Settings, then 'Display language: English' (or 'Restricted Mode: Off'), Sift has no dialog, and 0 ytd-multi-page-menu-renderer are visible. In original mode the same item opens 'Display language | Buttons and display text on this browser | Afrikaans ...'. With Sift shown, a plain JS .click() on the item's inner <a> opens the sub-page, and Sift then shows it as a dialog ('Back / Display language / ...'). So Sift's replay is at fault, not the site. The sheet's aria-label is 'Appearance: Light', and 'Appearance: Light' is plain text, not a button. In app.tsx DialogView, name = d.title || firstLine(d.blocks) || page.title.
- **fix**: In src/content/proxy.ts click() (or in the action's ref choice in extract/generic.ts), target the menu item's inner a#endpoint inside tp-yt-iron-dropdown/ytd-multi-page-menu-renderer. Skip the pointerdown/mousedown sequence there, since el.click() alone works. For the name, give the dialog a title from the opener's label ('Settings') in findDialog, not firstLine().

## F302 [medium] Search suggestions never appear when typing in Sift's YouTube search box
- **where**: YouTube home/search/watch, Sift header search field
- **evidence**: I typed 'how to fold a fitted sheet' with real keys into Sift's field. The page field got the value, but after 2 s the original's suggestion container was empty and hidden, and Sift showed no list (the input has no aria-expanded or aria-controls). In original mode, typing the same text into YouTube's box shows 'how to fold a fitted sheet / ... easily / ... funny video / ... properly / ... correctly'. Enter does search. Screenshots: /home/nico/projects/sift-test-1/research/shots/R4T1-search-suggest.png (Sift), R4T1-search-suggest-orig.png (original)
- **repro**: SIFT_PORT=9461 SIFT_TAB=T1-youtube bun scripts/act.ts goto:https://www.youtube.com/ wait:5000 "type:input[type=search]=>how to fold a fitted sheet" wait:2000 "eval:[...document.querySelectorAll('[role=listbox]')].map(l=>l.checkVisibility()+':'+l.querySelectorAll('[role=option]').length)" gives ['false:0'].
- **suspectedCause**: YouTube's searchbox fetches suggestions on focus plus keydown/input events on its own input. The replay sends only input/change, or the page field is not focused, so YouTube never opens its list, and Sift has nothing to anchor. Same family as F81 (Google Maps).
- **verdict**: Reproduced twice in Sift mode: once on home with 'how to fold a fitted sheet' and once on search with ' recipe' appended. The page field gets the value, but the only [role=listbox] is 'false:0', and there is no .sheet.suggest. In original mode, typing the same text with real keys gives a visible listbox with 14 options ('how to fold a fitted sheet easily / ...'). proxy.ts setValue() only sets the value and fires one 'input' event.
- **fix**: In src/content/proxy.ts setValue(), for search inputs also run focus() on the page field (inside withoutShield) and dispatch keydown/keyup for the typed character, as typing does. Or add a YouTube-specific path that does this for ytSearchboxComponent's input, then anchor Sift's suggestion sheet to the listbox that opens.

Focus a Sift button, press:l and press:ArrowRight, and compare document.querySelector('#movie_player video').currentTime before and after.

Tab to '56 replies' and press Enter, then wait 7 s. Read the focused element by walking document.activeElement through shadowRoot.activeElement: it is '62 replies', top about 1480.
- **suspectedCause**: When the focused 'N replies' button disappears on re-render, Sift's focus restore picks the next action in document order and does not scroll it into view. The thread's own new 'Show more replies' or its first reply should take focus.
- **verdict**: Reproduced twice with keyboard input only, at 1280x900. I tabbed to '2,460,502 Comments', pressed Enter, tabbed to '56 replies' (top 428) and pressed Enter. The button labels differ from the report because the comment order changed, but the behavior is the same. In index.ts refocusNow(), the 'near' fallback calls tryFocus(now) without scroll and picks the next control in document order.
- **fix**: In src/content/index.ts refocusNow(): when the spot was in a list item whose control disappeared, prefer that item's new controls ('Show more replies', 'Hide replies' or the first reply) over spot.near. Call tryFocus(..., true) in the near fallback so the focused control scrolls into view.

## F312 [low] Image-only comment shows only the text '[Comment image attachment]'; the image is not shown
