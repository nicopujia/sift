  p: This is an attempt to clear up several (possible) misunderstandings about closures that appear in some of the other answers.
    li: A closure is not only created when you return an inner function. In fact, the enclosing function does not need to return at all in order for its closure to be created. You might instead assign your inner function to a va
    li: A closure does not reference a copy of the old values of variables in its scope. The variables themselves are part of the closure, and so the value seen when accessing one of those variables is the latest value at the ti
    li: The "variables" in a closure include any named functions declared within the function. They also include arguments of the function. A closure also has access to its containing closure's variables, all the way up to the g
    li: Closures use memory, but they don't cause memory leaks since JavaScript by itself cleans up its own circular structures that are not referenced. Internet Explorer memory leaks involving closures are created when it fails

  p: The secrets for JavaScript functions are the private variables
  p: Every time you call it, the local variable "name" is created and given the name "Mary". And every time the function exits the variable is lost and the name is forgotten.
  p: As you may guess, because the variables are re-created every time the function is called, and nobody else will know them, there must be a secret place where they are stored. It could be called Chamber of Secrets or stack
  p: But, in JavaScript, there is this very special thing that functions which are created inside other functions, can also know the local variables of their parents and keep them as long as they live.
  p: So, as long as we are in the parent -function, it can create one or more child functions which do share the secret variables from the secret place.
  p: But the sad thing is, if the child is also a private variable of its parent function, it would also die when the parent ends, and the secrets would die with them.
  p: So to live, the child has to leave before it's too late
  p: And now, even though Mary is "no longer running", the memory of her is not lost and her child will always remember her name and other secrets they shared during their time together.
  p: So, if you call the child "Alice", she will respond
  p: That's all there is to tell.

    [link] LexicalEnvironment
  p: The process consists of two steps:
    li: First, when a function f is created, it is not created in an empty space. There is a current LexicalEnvironment object. In the case above, it’s window (a is undefined at the time of function creation).
    [link] Enter image description here
  p: When a function is created, it gets a hidden property, named [[Scope]], which references the current LexicalEnvironment.
    [link] Enter image description here
  p: If a variable is read, but can not be found anywhere, an error is generated.
  p: Nested functions
  p: Functions can be nested one inside another, forming a chain of LexicalEnvironments which can also be called a scope chain.
    [link] Enter image description here
  p: So, function g has access to g, a and f.
  p: Closures
  p: A nested function may continue to live after the outer function has finished:
    [link] Enter image description here
  p: Marking up LexicalEnvironments:
    [link] Enter image description here
  p: As we see, this.say is a property in the user object, so it continues to live after User completed.
  p: And if you remember, when this.say is created, it (as every function) gets an internal reference this.say.[[Scope]] to the current LexicalEnvironment. So, the LexicalEnvironment of the current User execution stays in mem
  p: The whole point is to ensure that if the inner function wants to access an outer variable in the future, it is able to do so.
  p: To summarize:
    li: The inner function keeps a reference to the outer LexicalEnvironment.
    li: The inner function may access variables from it any time even if the outer function is finished.
    li: The browser keeps the LexicalEnvironment and all its properties (variables) in memory until there is an inner function which references it.
  p: This is called a closure.
